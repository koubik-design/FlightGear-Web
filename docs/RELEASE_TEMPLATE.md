# GitHub Release checklist and template

Use this template for each **reviewed, reproducible milestone**. Do not create a GitHub Release for every intermediate CI run. Each pushed commit already receives a GitHub Actions run, and the CI smoke-test output is available under **Actions → workflow run → Artifacts**.

## Release fields

- **Tag:** `v<major>.<minor>.<patch>-phase<N>` for pre-1.0 engineering milestones.
- **Title:** `FlightGear-Web Phase <N> — <milestone name>`
- **Description:** State exactly what is implemented, what was tested, known limitations, and the source commit.
- **Attached file:** Only attach an artifact that has been generated by CI and verified. Prefer a ZIP for browser assets, or a `.tar.gz` for source snapshots. Never rename a compiler smoke test into a simulator release.

## Copy-and-edit release description

```markdown
## Summary
<What this milestone actually delivers>

## Build and verification
- Source commit: <full commit SHA>
- Toolchain: <exact Emscripten image/version>
- CI run: <link to successful workflow run>
- Tests performed: <commands and browser/device matrix, if applicable>

## Included files
- <artifact filename> — <what it contains>

## Known limitations
- <important missing or experimental functionality>

## Important
This is an experimental browser-port milestone, not an official FlightGear release.
```

## Phase 1 example (do not publish as a simulator build)

- **Tag:** `v0.1.0-phase1-toolchain`
- **Title:** `FlightGear-Web Phase 1 — Emscripten Toolchain Baseline`
- **Description:** `Establishes a pinned Emscripten Docker environment and validates CMake-to-WebAssembly compilation with a minimal C++ smoke test. Does not contain FlightGear, SimGear, OpenSceneGraph, aircraft, scenery, or a playable simulator.`
- **File:** No simulator release file. The CI artifact named `wasm-toolchain-smoke-test` is diagnostic output only and expires after 7 days. Do not attach it as a playable build.

## Important distinction

A GitHub Actions artifact is generated by a workflow and has a retention period. A GitHub Release is a manually published, versioned distribution. They are not interchangeable. The current GitHub connection can commit repository files and inspect workflow runs/artifacts, but cannot create or publish a GitHub Release.
